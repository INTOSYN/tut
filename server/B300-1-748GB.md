# NVIDIA DGX Station GB300（252GB HBM3e）MIG 切分教程

适用于新款 NVIDIA DGX Station：

- GB300 Grace Blackwell Ultra Desktop Superchip
- 1 张 NVIDIA Blackwell Ultra GPU（B300）
- 252GB HBM3e GPU 显存，带宽 7.1TB/s
- 496GB LPDDR5X CPU 内存，带宽 396GB/s
- 通过 NVLink-C2C 组成最多 748GB 的一致性内存空间
- 最多支持 7 个 MIG 实例

产品规格：[NVIDIA DGX Station](https://www.nvidia.com/en-us/products/workstations/dgx-station/)



## 1. 两类内存

DGX Station 有两类内存：

| 类型 | 容量 | 带宽 | 说明 |
|---|---:|---:|---|
| GPU HBM3e | 252GB | 7.1TB/s | MIG 直接切分的 GPU 本地显存 |
| CPU LPDDR5X | 496GB | 396GB/s | Grace CPU 系统内存，通过 NVLink-C2C 与 GPU 保持一致性访问 |

MIG Profile 中的 `31gb`、`126gb`、`251gb` 等数字指 GPU HBM 配额。496GB LPDDR5X 不会按 MIG Profile 分成每个实例的专属显存，也不应当计入 MIG HBM 容量。

硬件架构说明：[NVIDIA DGX Station Development Guide](https://docs.nvidia.com/dgx/dgx-station-development-guide/overview.html)

## 2. 重要注意事项

- 修改 MIG 前必须停止目标 GPU 上的训练、推理和容器任务。
- 创建或删除 MIG 实例会改变 GPU 设备拓扑和 MIG UUID。
- 使用 MIG 后，原先保存的 GPU/MIG UUID 可能失效。
- DGX Station 是单 GB300 GPU，通过 NVLink-C2C 连接 Grace CPU，没有 NVSwitch Fabric。
- **不要安装或启动 `nvidia-fabricmanager`**；DGX Station 通常没有这个服务。
- 建议通过 SSH 或 BMC 操作，避免当前桌面会话持有 GPU。

## 3. 找到 GB300 的 GPU 编号

```bash
nvidia-smi --query-gpu=index,name,compute_cap,uuid --format=csv
```

找到名称为 `NVIDIA GB300` 的行。例如：

```text
index, name, compute_cap, uuid
1, NVIDIA GB300, 10.3, GPU-xxxxxxxx-...
```

以下示例假设它是 GPU 1：

```bash
GPU_INDEX=1
```

如果 GB300 是 GPU 0，请改为：

```bash
GPU_INDEX=0
```

## 4. 查看当前 MIG 状态

```bash
nvidia-smi -i "$GPU_INDEX" -q | grep -A2 "MIG Mode"
```

查看已有实例：

```bash
sudo nvidia-smi mig -lgi -i "$GPU_INDEX"
sudo nvidia-smi mig -lci -i "$GPU_INDEX"
```

其中：

- GI：GPU Instance。
- CI：Compute Instance。

## 5. 检查 GPU 是否正在被占用

```bash
nvidia-smi
sudo fuser -v /dev/nvidia*
docker ps --format 'table {{.ID}}\t{{.Names}}\t{{.Status}}'
```

停止使用 GB300 的程序和容器后再继续。

> [!WARNING]
> 不要直接杀死不认识的系统进程。先确认进程对应的服务和工作负载。

## 6. 启用 MIG 模式

```bash
sudo nvidia-smi -i "$GPU_INDEX" -mig 1
```

验证：

```bash
nvidia-smi -i "$GPU_INDEX" -q | grep -A2 "MIG Mode"
```

预期结果：

```text
MIG Mode
    Current                           : Enabled
```

如果显示 `Pending`，确认 GPU 已无进程占用，然后重启系统再检查。

## 7. 查看本机实际支持的 Profile

不要根据营销显存容量推算 Profile，直接读取驱动公布的 Profile：

```bash
nvidia-smi mig -lgip -i "$GPU_INDEX"
```

再查看每个 Profile 的合法放置位置：

```bash
nvidia-smi mig -lgipp -i "$GPU_INDEX"
```

### 常用 Profile ID

DGX Station 的 Profile 名称会随驱动分支变化，但 ID 相对稳定：

| ID | R59x 常见名称 | R61x 常见名称 | 典型用途 |
|---:|---|---|---|
| 19 | `1g.35gb` | `1g.31gb` | 小模型、开发测试 |
| 20 | `1g.35gb+me` | `1g.31gb+me` | 小模型及媒体引擎 |
| 15 | `1g.70gb` | 以本机输出为准 | 较大显存、较少算力 |
| 14 | `2g.70gb` | 以本机输出为准 | 中型模型 |
| 9 | `3g.139gb` | `3g.126gb` | 量化 70B 等较大模型 |
| 5 | `4g.139gb` | `4g.126gb` | 相近显存、更多计算资源 |
| 0 | `7g.278gb` | `7g.251gb` | 完整 GPU 的单 MIG 实例 |

> [!IMPORTANT]
> 创建实例时推荐使用 Profile ID，不要硬编码 `1g.35gb` 或 `1g.31gb`。必须以本机 `nvidia-smi mig -lgip` 和 `-lgipp` 的结果为准。

NVIDIA 当前的 DGX Station 指南还指出：部分 R61x 软件栈中，`-lgip` 的 `Free/Total` 可能高估实际可创建实例数；实机测试曾出现最多只能创建 3 个 `1g` 实例的情况。因此，“官方最多 7 个 MIG”不代表当前驱动下任意布局都能创建成功。

参考：[NVIDIA DGX Station MIG 配置说明](https://github.com/NVIDIA/dgx-spark-playbooks/blob/main/nvidia/station-ai-skills/assets/skills/mig-configure/SKILL.md)

## 8. 清除已有 MIG 实例

如果需要重新切分，先删除 CI，再删除 GI：

```bash
sudo nvidia-smi mig -dci -i "$GPU_INDEX"
sudo nvidia-smi mig -dgi -i "$GPU_INDEX"
```

确认已经清空：

```bash
sudo nvidia-smi mig -lgi -i "$GPU_INDEX"
sudo nvidia-smi mig -lci -i "$GPU_INDEX"
```

## 9. 创建 MIG 布局

基本格式：

```bash
sudo nvidia-smi mig -cgi <PROFILE_ID列表> -C -i "$GPU_INDEX"
```

`-C` 表示创建 GI 后，同时创建默认 CI。

### 方案 A：三个小实例

适合多个小型模型、开发环境或推理服务：

```bash
sudo nvidia-smi mig -cgi 19,19,19 -C -i "$GPU_INDEX"
```

在 R61x 驱动上通常显示为三个 `1g.31gb` 实例。

### 方案 B：一个大实例加两个显存型实例

适合同时运行一个较大模型和两个较小任务：

```bash
sudo nvidia-smi mig -cgi 9,15,15 -C -i "$GPU_INDEX"
```

### 方案 C：完整 GPU 的单个隔离实例

```bash
sudo nvidia-smi mig -cgi 0 -C -i "$GPU_INDEX"
```

在 R61x 驱动上一般显示为 `7g.251gb`。

### 尝试创建 7 个小实例

产品规格标称最多支持 7 个 MIG。如果本机 `-lgipp` 确认存在足够合法位置，可以尝试：

```bash
sudo nvidia-smi mig \
  -cgi 19,19,19,19,19,19,19 \
  -C -i "$GPU_INDEX"
```

如果报 `Insufficient Resources` 或 `Invalid combination`，不要反复强制执行。清空实例后使用三个小实例方案：

```bash
sudo nvidia-smi mig -dci -i "$GPU_INDEX"
sudo nvidia-smi mig -dgi -i "$GPU_INDEX"
sudo nvidia-smi mig -cgi 19,19,19 -C -i "$GPU_INDEX"
```

## 10. 验证结果

```bash
nvidia-smi -L
sudo nvidia-smi mig -lgi -i "$GPU_INDEX"
sudo nvidia-smi mig -lci -i "$GPU_INDEX"
nvidia-smi
```

R61x 驱动上的输出可能类似：

```text
GPU 1: NVIDIA GB300 (UUID: GPU-xxxxxxxx-...)
  MIG 1g.31gb Device 0: (UUID: MIG-xxxxxxxx-...)
  MIG 1g.31gb Device 1: (UUID: MIG-xxxxxxxx-...)
  MIG 1g.31gb Device 2: (UUID: MIG-xxxxxxxx-...)
```

实际名称和 UUID 以你的机器为准。

## 11. 使用 MIG 实例

### 裸机程序

先从 `nvidia-smi -L` 复制目标 MIG UUID：

```bash
export CUDA_VISIBLE_DEVICES=MIG-xxxxxxxx-...
./your_app
```

验证当前进程只能看到该 MIG：

```bash
CUDA_VISIBLE_DEVICES=MIG-xxxxxxxx-... nvidia-smi
```

### Docker

```bash
docker run --rm \
  --gpus '"device=MIG-xxxxxxxx-..."' \
  <支持GB300的CUDA镜像> \
  nvidia-smi
```

例如：

```bash
MIG_UUID=MIG-xxxxxxxx-...

docker run --rm \
  --gpus "device=$MIG_UUID" \
  nvcr.io/nvidia/pytorch:26.01-py3 \
  nvidia-smi
```

## 12. 修改现有布局

每次修改布局都要：

1. 停止使用旧 MIG UUID 的任务。
2. 删除 CI。
3. 删除 GI。
4. 创建新布局。
5. 重新获取 MIG UUID。

```bash
sudo nvidia-smi mig -dci -i "$GPU_INDEX"
sudo nvidia-smi mig -dgi -i "$GPU_INDEX"
sudo nvidia-smi mig -cgi 9,15,15 -C -i "$GPU_INDEX"
nvidia-smi -L
```

## 13. 恢复整卡模式

停止所有 MIG 工作负载后执行：

```bash
sudo nvidia-smi mig -dci -i "$GPU_INDEX"
sudo nvidia-smi mig -dgi -i "$GPU_INDEX"
sudo nvidia-smi -i "$GPU_INDEX" -mig 0
```

验证：

```bash
nvidia-smi -i "$GPU_INDEX" -q | grep -A2 "MIG Mode"
nvidia-smi -L
```

预期结果：

```text
MIG Mode
    Current                           : Disabled
```

DGX Station 不需要启动 Fabric Manager。禁用 MIG 后，单 GPU 的 NVLink-C2C 会由平台自动恢复。

## 14. 常见错误

### `In use by another client`

GPU 仍被进程、容器或服务占用：

```bash
sudo fuser -v /dev/nvidia*
nvidia-smi
docker ps
```

停止对应工作负载后重试。

### `Insufficient Resources`

可能原因：

- `-lgip` 显示的计算切片数量高于实际可放置数量。
- 固定 HBM Slice 位置不允许该组合。
- 已有 GI/CI 没有删除。

处理方法：

```bash
sudo nvidia-smi mig -dci -i "$GPU_INDEX"
sudo nvidia-smi mig -dgi -i "$GPU_INDEX"
nvidia-smi mig -lgipp -i "$GPU_INDEX"
```

然后换用 NVIDIA 已验证的 `19,19,19`、`9,15,15` 或 `0` 布局。

### Profile 名称和文档不同

这是驱动分支差异：

- R59x 可能显示 `1g.35gb`、`3g.139gb`、`7g.278gb`。
- R61x 可能显示 `1g.31gb`、`3g.126gb`、`7g.251gb`。

使用相应的 Profile ID 创建，不要依赖名称。

### MIG 模式一直是 `Pending`

确认没有 GPU 进程后重启系统。如果仍然异常，再检查驱动、固件和系统软件是否为 DGX Station 认证版本。
